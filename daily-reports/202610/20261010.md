## Authentik の検証環境構築（kind）

- Keycloak + oauth2-proxy 相当で、Google 認証とパスワード認証を両立できる OSS を比較し、IdP と認証プロキシが一体の Authentik を検証対象に選んだ
  - 比較候補: Keycloak / Authelia / Zitadel / Logto / SuperTokens / Casdoor / Ory Kratos / Pomerium。Authelia は外部 IdP 連携がないため対象外
  - アプリ組み込み型（Cognito 的な SDK 利用）なら Zitadel / Logto の方が素直、既存アプリの前段に認証をかけるなら Authentik という整理
- Authentik（chart 2026.8.3）を Flux の HelmRepository / HelmRelease で管理し、ルートの kustomization に含めた
  - 最初は helm 直接インストールで検証し、作り直しを手作業なしにするため HelmRelease 化した
  - values は ConfigMap 化して valuesFrom で渡し、helm template での検証を維持
  - GitHub 同期なしでも Flux controller だけ入れて kubectl apply -k で投入できる
  - 同 chart 版は Redis 依存がなく、同梱 PostgreSQL のみ
- 手作業を Secret 作成だけにした
  - secret_key・DB パスワード・akadmin の bootstrap パスワード・Google の Client ID / Secret を手動作成の Secret から注入し、リポジトリに値を置かない
  - akadmin は bootstrap 環境変数で作成し、初期セットアップ画面を不要にした
  - kind を作り直して手順どおり再構築できることを確認した
- リポジトリに CLAUDE.md を新設し、検証コマンド（ルート・authentik・caddy-demo の kustomize build、Authentik chart の helm template）を定義した。日報の保存先もこのリポジトリにした
- Google OAuth ソースを blueprint で定義し、ユーザー名をメールアドレスから自動設定する property mapping で、Google 初回ログイン時のユーザー名入力をスキップさせた
- Caddy の動作確認アプリを作り、Authentik の埋め込み outpost による forward auth で保護した
  - アプリ本体は独立した namespace・ディレクトリ（caddy-demo）に分け、Proxy Provider / Application / outpost 割り当ての blueprint は Authentik 側に置いた
  - 認証後に X-Authentik-* ヘッダを表示するページと、挨拶ページを用意
  - Google ログイン（external ユーザー）・パスワードログインの両方でアプリに入れることを確認した
- パスワードログインに二段階認証（TOTP / パスキー）を必須化した。未登録ユーザーはログイン時に登録を強制し、Google ログインは対象外
  - 既定の MFA 検証ステージを blueprint で上書きした。既定 blueprint はこのステージを名前だけで定義しているため、再適用されても設定は戻らないことを確認した

### 申し送り

- Colima の VM が 2CPU / 2GiB では kind + Authentik が OOM で不安定になるため、4CPU / 8GiB に拡張した
- 初期セットアップのフローを直接開くと完了フラグが立たず、以降 `/` が 500 エラー画面に転送され続ける。bootstrap 化した現構成では初期セットアップ画面は出ない
- Google 経由で作られるユーザーは external になり、Authentik 自体のユーザーポータルには入れない（連携したアプリには入れる）。MFA も自分で後から登録できないため、ログイン時登録の強制が必要
- blueprint の outpost エントリは埋め込み outpost の provider 一覧を上書きするため、アプリ追加時は blueprint に追記する
- 初回起動時の blueprint 適用で競合が出た。依存 blueprint の適用順を明示し、worker のスレッド数を 1 にして解消した
- rollout 中に旧 worker が新しい blueprint を読めず一時的に error になることがある。worker 再起動で解消する
- ログイン状態は Authentik のドメインで共有される（SSO）。アプリごとに分けるなら Authentik 側のドメインを Brand で分ける。アプリ単位のアクセス制限は Application へのグループ / ポリシー紐付けで行う
